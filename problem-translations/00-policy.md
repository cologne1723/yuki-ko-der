# 공통 적용 원칙

번역·수정·검토·기계 검수·작업 배정에 공통으로 적용한다. 세부 규칙보다 먼저 읽는다. 규칙·인수인계 작성 요청은 실제 번역·검수·승인 실행 요청이 아니다.

## 지시와 근거의 우선순위

- 시스템·개발자 지시를 준수하는 범위에서 현재 사용자 요청과 기존 대화의 명시적 확정·정정을 먼저 적용한다. 같은 대상에 대한 최신 정정을 따르며 이미 허가된 범위를 매 단계 다시 승인받지 않는다.
- 공유 규칙과 glossary는 사용자 확정 지시를 구현하는 기본 기준이다. glossary 누락, 검색 0건, 검사 메시지, 옛 배정 예시는 사용자 결정을 취소하지 않는다. 충돌하면 확정 표기를 유지하고 불일치 위치를 보고한다.
- 문제별 예외는 해당 대상과 문맥에만 적용한다. 특정 범위의 제외·수정·승인 허가를 다른 문제나 앞으로의 모든 작업에 확대하지 않는다.
- 규칙은 최신 작업 트리에서 읽는다. 인수인계에서 전달받은 구체적인 사용자 결정을 일반 규칙을 근거로 되돌리지 않는다. 사용자 결정이 아닌 옛 배치 예시·완료 기록은 현재 권한의 근거가 아니다.
- 미커밋 diff 전체를 사람 수정으로 단정하지 않는다. 동시 편집이 있으면 최신 파일로 다시 대조하고, 기존 변경을 보존하며 담당 변경만 직접 패치한다.

## 이름과 호칭

| 상황 | 처리 |
| --- | --- |
| 사용자가 번역·표기·원문 유지를 확정함 | 그 결정을 유지한다. glossary 누락이나 다른 규칙의 예를 이유로 바꾸지 않는다 |
| 현재 한국어·라틴 표기가 있고 근거가 불확실함 | 현재 표기를 보존하고 번호·원문·현재 표기·불확실한 이유를 보고한다. 일본어로 복원하지 않는다 |
| 아직 번역하지 않은 이름에 사용자 결정과 glossary 대응이 모두 없음 | 새 음역·뜻풀이를 만들지 않고 이름·호칭 전체를 원문으로 남겨 보고한다 |
| glossary 조회가 비어 있음 | 조회된 항목이 없다는 뜻이다. 기존 표기의 오류나 사용자 미확정을 뜻하지 않는다 |
| 이름 재번역·복원을 명시적으로 요청받음 | 지정한 이름·문제·방향만 수정하며 다른 확정 표기는 유지한다 |

일반적인 검수·규칙 적용 요청만으로 한국어 이름을 가타카나·한자·히라가나로 되돌리지 않는다. 원문이 라틴 문자이면 작품 지식으로 가타카나를 새로 만들지 않는다. `sourceTitle`, 코드, 실제 예제 데이터의 원문 보존은 별개이며 이 원칙을 이유로 번역하지 않는다.

확정 지시의 예는 `田中 → 다나카`, `太郎 → 타로`, `茜 → 아카네`, `格子点大好きbot → 격자점좋아bot`이다. 확정 이름의 씨·군·쨩을 유지하며 bot 이름은 확정 한국어 표기에서 공백 없이 `bot`을 쓴다. 원문부터 라틴 문자인 `Mami`, `Homura`, `Madoka`, `Walpurgisnacht`도 임의로 재표기하지 않는다. 이 예 목록에 없다는 이유로 기존 이름을 되돌리지 않는다.

확정 표기·예외는 문제별 glossary 조회와 전달받은 사용자 결정으로 확인한다. glossary 등록을 맡았다면 확정 내용을 등록·검증한다. 개별 문제만 담당한다면 누락을 부모에게 보고한다. 실제 등록 없이 등록 완료라고 하지 않는다.

## 원문 보존과 최소 수정

- 원문 전체의 의미·정의·조건·데이터를 대조한다. 간결화는 중복 설명을 줄이는 작업이며 필요한 입력 형식·조건·예제를 삭제하는 작업이 아니다.
- 기존 문서를 빈 골격에서 다시 쓰지 않는다. 확인한 오류·규칙 위반만 허가 범위에서 수정한다. 허용된 문체·한국어 수량 표현·동등한 표기를 취향 때문에 바꾸지 않는다.
- 원문 보존은 번역을 원문 언어로 되돌리라는 뜻이 아니다. 사용자 확정 번역, 등록된 원문 오류 보정과 번역 이미지 대응을 먼저 확인한다. 이미 확인한 원문 오류를 재도입하지 않는다.
- 명시된 원문 형식은 보존하되 원문에 없는 `Ans` 출력 블록이나 반복 변수 설명은 추가하지 않는다. 수량의 수식 표기를 적용하려고 한국어 수량 표현을 숫자로 강제 변환하지 않는다.
- 충돌이 불확실하면 근거를 기록한다. 원문·번역을 추측으로 바꾸거나 검사기를 고쳐 숨기지 않는다.

## 범위와 검토 상태

| 요청 | 허용되는 결과 |
| --- | --- |
| 검토·보고만 | 발견 사항과 근거를 보고한다. 번역·이미지·검토 상태를 변경하지 않는다 |
| 번역·수정 | 지정 범위를 수정·검증한다. 새 번역의 기본값은 `humanReview: []`, `machineReview: unreviewed`다 |
| 기계 검수 | 전체 대조·검증으로 기계 상태를 판정·기록한다. 기존 `approved`를 이번 검토 완료 근거로 재사용하지 않는다 |
| 사람 승인본 수정 | 해당 승인본의 명시적 허가 범위를 따른다. 기록 삭제 허가를 추정하거나 보호 우회 목적으로 `humanReview`를 비우지 않는다 |
| 규칙·인수인계 작성 | 지침을 수정한다. 문제 번역 일괄 변경·검수 실행·승인·배포로 확대하지 않는다 |

사람 승인과 기계 검수는 독립적이다. 기계 검수 요청이 있으면 별도 사람 승인을 선행 조건으로 만들지 않으며 기계가 사람 ID를 추가하지 않는다. 번역 내용·사람 승인 기록의 보호와 허가된 기계 상태 판정을 구분한다. 커밋·푸시·배포는 명시적 요청에 따른다.

일괄 수정은 루트 `AGENTS.md`의 대상·범위 허가를 따른다. 일반 수정 권한을 자동 치환 권한으로 확대하지 않으며, 이미 명시적으로 허용된 일괄 범위를 다시 확인받지는 않는다.

## 검사와 배정

- 번역과 기존 문서 검토의 상태 검사 옵션을 구분한다. 명령은 [04-verification.md](04-verification.md)를 따른다. 검사 통과를 위해 승인 기록을 지우지 않는다.
- 검색 일치는 확인 후보일 뿐 오류 판정이 아니다. `rg` 종료 코드 1은 일치 없음이며 실행 오류와 구분한다. 허용된 표현이나 확정 표기를 검색 결과에서 없애려고 수정하지 않는다.
- 자동 검사 통과만으로 의미 검토를 대신하지 않는다. 실패도 번역 오류·도구 오탐·지원 누락·실행 실패로 구분해 근거와 실제 결과를 기록한다. 미확인 범위를 통과라고 쓰지 않는다.
- 부모는 자식에게 담당 범위와 수정·상태 기록 권한뿐 아니라 최신 사용자 정정, 확정 이름, 원문 유지 예외를 전달한다. 경로만 전달하고 대화의 결정을 빠뜨리지 않는다.
- 부모는 최종 diff에서 이름의 일본어 복원, 사람 수정의 재도입·누락, 승인 기록 우회 변경을 확인한다. 옛 모델·슬롯·단계 예시는 현재 권한이나 도구 지원을 만들지 않는다.
