이 문제는 yukicoder April fool contest 2019의 문제로 출제되었습니다.

2023/07/09 업데이트: 저지 코드가 Ruby3.2에 대응하지 못했기 때문에 저지 코드를 수정하고 재저지를 진행했습니다.

재저지 후 스페셜 저지가 AC로 판정했는데도 일부 제출이 TLE로 판정되는 경우가 있는 것 같습니다.

## 문제 설명

입력으로 제출한 소스 코드가 주어집니다.

단, 문자 코드가 $32$ 이상 $126$ 이하인 어떤 $1$byte가 문자 코드가 $32$ 이상 $126$ 이하인 서로 다른 $1$byte로 바뀌어 있습니다.

바뀐 위치($0$부터 세는 바이트 단위), 바뀌기 전 문자, 바뀐 후 문자를 표준 출력에 출력하세요.

소스 코드가 $3\,000$byte를 초과하거나 소스 코드 안에 바뀔 문자가 존재하지 않는 경우(예를 들어 개행만 있는 경우)는, 문자열 `WA`를 입력으로 받은 뒤 WrongAnswer가 됩니다.

문자 코드가 $33$ 이상 $126$ 이하인 문자를 다음과 같이 나열합니다. 문자 코드 $32$는 반각 공백입니다.

```text
!"#$%&'()*+,-./0123456789:;<=>?@ABCDEFGHIJKLMNOPQRSTUVWXYZ[\]^_`abcdefghijklmnopqrstuvwxyz{|}~
```

또한, **프로그램은 C 또는 C++14로 작성해야 합니다.**

그 밖의 언어(Ruby, Python 등)는 WrongAnswer가 됩니다.

제출하는 프로그램은 다음 컴파일을 실행했을 때 $2$개의 컴파일 명령 중 적어도 $1$개가 종료 코드 $0$을 반환해야 합니다.

$2$개의 컴파일 명령이 모두 종료 코드 $0$을 반환하는 경우에는 C 언어 코드로 제출한 것으로 해석합니다.

```text
gcc7 -x c -std=c11 _filename_
g++ -x c++ _filename_
```

23:58 추가: **C++ 컴파일 옵션에서 `-std=gnu++14`를 제외했습니다.**

## 입력

문자 코드가 $32$ 이상 $126$ 이하인 어떤 $1$byte가 문자 코드가 $32$ 이상 $126$ 이하인 서로 다른 $1$byte로 바뀐 제출 소스 코드가 주어집니다.

## 출력

$1$번째 줄에 바뀐 위치를 $0$부터 세는 바이트 단위로 출력하세요.

$2$번째 줄에 바뀌기 전 문자를 `"`로 감싸서 출력하세요.

$3$번째 줄에 바뀐 후 문자를 `"`로 감싸서 출력하세요.

마지막 개행은 있어도 없어도 됩니다.

## 힌트

리액티브 문제로 구현되어 있으므로, 일반 문제에서는 발생하지 않지만 리액티브 문제에서는 발생하는 것과 같은 WA나 TLE가 존재할 수 있습니다.

예를 들어 EOF가 오지 않는 것처럼 동작하므로, C 언어에서 `while(getchar() != -1);`라고 작성하면 TLE가 됩니다.

제출한 프로그램의 종료 코드가 $0$이 아니더라도 반드시 RE가 되는 것은 아닙니다.

## 예제

### 예제 1 {file=""}

다음 코드를 제출했다고 합시다.

```text
main(){
  printf("10\n\"p\"\n\"m\"");
}
```

저지에 의해 다음과 같이 바뀌었다고 합시다. 이 바뀐 코드는 표준 입력으로 주어집니다.

#### 입력

```text
main(){
  mrintf("10\n\"p\"\n\"m\"");
}
```

`p`에서 `m`으로 바뀌었습니다.

또한 `m,a,i,n,(,),{,개행,반각 SP,반각 SP,p,...`에서 $0$부터 세어 $10$번째 바이트가 바뀌었다는 것을 알 수 있습니다.

따라서 다음을 출력해야 합니다.

#### 출력

```text
10
"p"
"m"
```
