## 이야기

atetubouくん은 콘테스트에 참가 중입니다. 구현이 무거운 문제를 콘테스트 종료 $3$분 전에 겨우 코딩해 제출하려고 합니다.

열심히 작성한 코드가 TLE가 되면 슬프므로 코드를 개선하려고 합니다.

## 문제 설명

현재 문제에서 시간이 오래 걸릴 것 같은 부분은 `for`문을 여러 겹 실행하는 부분입니다.

```text
for i <- 0..X
    for j <- 0..X
        for k <- 0..X
            for l <- 0..X
                if i + j + k + l == X:
                    //program
```

이를 다음처럼 개선할 수 있다는 것을 알아냈습니다.

```text
for i <- 0..X
    for j <- 0..(X-i)
        for k <- 0..(X-i-j)
            l <- X-i-j-k
                //program
```

개선하고 나니 콘테스트 종료까지 $10$초가 남았습니다. `//program` 부분이 $T$번 실행되면 시간 안에 끝난다고 예상한 atetubouくん은 실제로 몇 번 실행되는지 알아보려 합니다. atetubouくん의 코드는 무사히 AC될까요?

`//program` 부분에서는 변수 $X$를 변경하지 않으며, `break` 등으로 반복문을 빠져나가지 않는다고 가정합니다.

## 입력

```text
$Q$
$D_1\ X_1\ T_1$
$D_2\ X_2\ T_2$
$\vdots$
$D_Q\ X_Q\ T_Q$
```

$Q$는 질의 수이고, $D_i,X_i,T_i$는 $i$번째 질의의 반복문 깊이, 변수 $X$의 값, 실행 횟수의 상한입니다.

## 제한

- $1 \leq Q \leq 10^4$: 질의 수
- $1 \leq D_i \leq 1\,500$: 개선 전 코드의 `for`문 깊이. 위 예에서는 $D=4$입니다.
- $1 \leq X_i \leq 1\,500$: 코드의 변수 $X$
- $0 \leq T_i \leq 10^{15}$: `//program` 실행 횟수의 상한. 이보다 많으면 TLE입니다.

## 출력

AC되면 `AC`를, TLE되면 `ZETUBOU`를 출력하세요. `ZETSUBOU`가 아니므로 주의하세요. 마지막에 개행을 넣으세요.

## 예제

### 예제 1 {file=""}

#### 입력

```text
3
1 3 1
2 4 50
3 3 9
```

#### 출력

```text
AC
AC
ZETUBOU
```

$1$번째 질의는 깊이가 $1$이므로 개선 후 $i\leftarrow X$ $1$번만 실행됩니다. $2$번째 질의는 개선 후 깊이가 $1$이고 $0$부터 $4$까지 $5$번 `//program`에 들어갑니다. $3$번째 질의는 $(i,j,k)$가 $(0,0,3),(0,1,2),(0,2,1),(0,3,0),(1,0,2),(1,1,1),(1,2,0),(2,0,1),(2,1,0),(3,0,0)$인 $10$번이므로 TLE입니다.
