## 문제

atetubou 군은 콘테스트에 참가 중입니다. 구현이 무거운 문제를 콘테스트 종료 3분 전에 겨우 코딩해 제출하려고 합니다.

열심히 작성한 코드가 TLE가 되면 슬프므로 코드를 개선하려고 합니다. 현재 문제에서 시간이 오래 걸릴 것 같은 부분은 `for`문을 여러 겹 실행하는 부분입니다.

```text
for i <- 0..X
    for j <- 0..X
        for k <- 0..X
            for l <- 0..X
                if i + j + k + l == X:
                    //program
```

이를 다음처럼 개선할 수 있다는 것을 알아냈습니다.

```text
for i <- 0..X
    for j <- 0..(X-i)
        for k <- 0..(X-i-j)
            l <- X-i-j-k
                //program
```

개선하고 나니 콘테스트 종료까지 10초가 남았습니다. `//program` 부분이 $T$번 실행되면 시간 안에 끝난다고 예상한 atetubou 군은 실제로 몇 번 실행되는지 알아보려 합니다. atetubou 군의 코드는 무사히 AC될까요?

`//program` 부분에서는 변수 $X$를 변경하지 않으며, `break` 등으로 반복문을 빠져나가지 않는다고 가정합니다.

## 입력

```text
Q
D_1 X_1 T_1
D_2 X_2 T_2
⋮
D_Q X_Q T_Q
```

- $1 \leq Q \leq 10^4$: 질의 수
- $1 \leq D_i \leq 1500$: 개선 전 코드의 `for`문 깊이
- $1 \leq X_i \leq 1500$: 코드의 변수 $X$
- $0 \leq T_i \leq 10^{15}$: `//program` 실행 횟수의 상한. 이보다 많으면 TLE입니다.

## 출력

AC되면 `AC`를, TLE되면 `ZETUBOU`를 출력하세요. `ZETSUBOU`가 아니므로 주의하세요. 마지막에 개행을 넣으세요.

## 샘플

### 입력 1 {file="stdin"}

```text
3
1 3 1
2 4 50
3 3 9
```

### 출력 1 {file="stdout"}

```text
AC
AC
ZETUBOU
```

첫 번째 질의는 깊이가 1이므로 개선 후 `i <- X` 한 번만 실행됩니다. 두 번째 질의는 개선 후 깊이가 1이고 0〜4까지 5번 `//program`에 들어갑니다. 세 번째 질의는 $(i,j,k)$가 $(0,0,3),(0,1,2),(0,2,1),(0,3,0),(1,0,2),(1,1,1),(1,2,0),(2,0,1),(2,1,0),(3,0,0)$인 10번이므로 TLE입니다.

### 입력 2 {file="stdin"}

```text
3
58 62 1000
12 34 56
987 65 1234
```

### 출력 2 {file="stdout"}

```text
ZETUBOU
ZETUBOU
ZETUBOU
```

atetubou 군은 절망했습니다.
