# 한국어 문제 번역 검토 지침

이 문서는 기존 번역을 검토하는 순서와 규칙 파일의 진입점이다. 번역과 동일한
규칙을 적용한다. 규칙을 기억해서 적용하지 말고, 각 단계의 시작 직전에 지정된
파일을 다시 읽는다. 아래 단계 설명은 규칙 파일 전체를 대신하지 않는다.

## 검토 목적과 승인 기준

기계 검수는 번역과 같은 공유 규칙 전체를 적용한다. 입력 형식, 수량 서식,
이름 표기, 원문 설명·링크·이미지 보존을 포함하여 명백한 규칙 위반이 하나라도
있으면 승인하지 않는다. 의미가 유지된다는 이유로 명시된 규칙을 면제하지 않는다.
규칙이 허용하는 선택 사항은 명백히 틀리지 않았다면 변경을 요구하지 않고 승인한다.

기계 검수 요청에서 `machineReview`를 판정하며 사람 검수는 `humanReview`로 별도
관리한다. 발견 사항과 근거는 완료 보고에 남기고, 상세 기록은 `data/reports/`에 둔다.
특정 배치의 보고서 작성 범위는 해당 요청을 따른다.

## 시작 전 확인

1. [REVIEW_WORKFLOW.md](REVIEW_WORKFLOW.md)에서 시작하여 저장소 지침을 읽는다.
   기존 대화에서 승인된 작업 범위와 사용자 정정을 유지한다.
2. 요청한 문제 번호를 중복 없이 확정하고, 검토만 하는지 수정까지 하는지 기록한다.
   승인·커밋·배포 요청은 각각 구분한다. 이미 허용된 작업을 다시 승인받지 않는다.
3. `git status --short`로 기존 변경을 확인한다. 담당 MDX와 이미지의 시작 상태를
   기록하여 기존 사용자 변경과 이번 수정이 섞이지 않게 한다. `git diff`에는
   기존 변경도 포함될 수 있고 미추적 파일은 나오지 않는다는 점을 고려한다.
4. 원문 HTML, 인덱스 레코드, 기존 MDX의 존재를 전체 대상에 대해 확인한다.
   없는 번역을 새로 작성하는 것은 번역 작업이므로 검토 대상으로 생성하지 않는다.
5. 문제별로 원문·MDX의 SHA-256, 시작 검토 상태, 현재 단계, 발견 사항, 검사 결과,
   미해결 사항을 추적한다. 파일이나 원문이 바뀌면 이전 검토 근거를 새 저장본에
   그대로 적용하지 않는다. 기록 파일이 필요하면 `data/reports/`에 둔다.
6. 서브에이전트를 배정하는 주체는 [실행 절차](REVIEW_ORCHESTRATION.md)를 먼저 읽는다.
   검토 기준은 아래 공유 규칙이며, 실행 절차는 이를 대체하지 않는다.

## 작업 순서

### 1. 원문·메타데이터·검토 대상 확인

[01-source.md](01-source.md)를 읽고 원문 HTML 전체와 저장된 번역 전체를 읽는다.
`index.json`의 정확한 `No`, `ProblemId`, 제목, 원문 해시를 번역 메타데이터와
대조한다. 현재 검토 상태와 요청된 검토·수정 범위를 확인한다. 원문이나 번역이
없거나 식별자가 충돌하면 영향을 받는 문제와 원인을 기록한다.

### 2. 의미와 한국어 문체 대조

`pnpm glossary -- data/problems-source/NUMBER.html`의 출력 항목만 읽은 뒤
[02-meaning.md](02-meaning.md)를 다시 읽는다. 원문의 각 블록에 대응하는 번역을
찾아 이야기, 정의, 조건, 예외, 입력, 제한, 출력, 공지, 힌트, 예제 설명의
누락·추가·오역과 용어·이름 표기를 확인한다. 가장 오해하기 쉬운 조건은 정의와
예제를 실제로 따라가며 검증한다. 확정할 수 없는 충돌은 추측하지 않고 기록한다.

### 3. 문서 구조와 수식·데이터 대조

[03-structure-and-format.md](03-structure-and-format.md)를 다시 읽고 저장본의
절 순서, 입력·출력 형식, 수식, 예제 제목과 데이터를 확인한다. 특히 입력 절을
검토할 때 입력 형식 규칙을 다시 확인한다. 설명용 형식과 실제 예제 데이터를
구분하여 원문과 행별로 대조한다. 코드, 링크, 이미지와 이미지 주변 설명도
원문에 대응시킨다. 수정한 경우 저장 파일을 다시 읽고 서식·이스케이프 보존을
확인한다.

### 4. 전체 대조와 자동 검사

[04-verification.md](04-verification.md)를 다시 읽고 그 안의 전체 대조, 검색,
렌더 확인과 검증 명령을 모두 수행한다. 검토만 하는 경우 검색으로 발견한 수정
대상은 보고하고, 수정 요청이 있으면 고친 뒤 전체 대조와 검사를 다시 수행한다.
자동 검사 통과는 의미 보존이나 사람 검토를 뜻하지 않는다. 검사기의 한계는
번역 오류와 구분해 기록하고, 통과를 위해 원문 데이터를 바꾸지 않는다.

### 5. 검토 결과와 상태 기록

[04-verification.md](04-verification.md)의 검토 기록 기준을 다시 읽는다.
발견 사항마다 문제 번호, 파일·위치, 위반 규칙, 원문 근거와 영향을 기록하고,
수정한 사항·남은 오류·원문 충돌·사람 확인 항목을 구분한다. 첫 오류에서 멈추지
말고 요청 범위 전체에서 확인 가능한 사항을 모아 보고한다.

실제로 수행한 검사와 결과, 수량 검색의 남은 일치와 예외 이유, 가장 오해하기
쉬운 조건과 대응 예제 근거를 완료 보고에 남긴다. 확인하지 못한 범위와 원인을
명시하고, 명백한 공유 규칙 위반·오류·모순이나 판정에 필요한 미확인 사항이 있으면 승인하지 않는다.

기계 검수 요청을 받으면 최종 저장본의 전체 대조와 검증 결과로 `machineReview`를
직접 판정·기록한다. 기계 승인에 대한 별도 사용자 확인은 요구하지 않는다.
명백한 공유 규칙 위반·오류·모순이나 판정에 필요한 미검증 범위가 남으면 `unreviewed`,
그렇지 않으면 `approved`다.
레거시 `reviewStatus: machine`은 미검수로 취급한다. 사람 검수는 `humanReview`로
검수자 ID 목록으로 별도 관리하며, 기계 검수 결과로 사람 ID를 추가하지 않는다.
새 번역의 기본 상태는 `humanReview: []`,
`machineReview: unreviewed`다.

## 단계별 증거와 완료 판정

| 단계 | 다음 단계로 넘기기 전에 남길 증거 |
| --- | --- |
| 1 | 실제 읽은 파일, 정확한 식별자·해시 대조, 시작 검토 상태, 누락·충돌 |
| 2 | 원문 블록과 번역 위치의 대응, 의미·용어 오류, 핵심 조건과 예제 근거 |
| 3 | 절·형식·수식·데이터·자산 대조 결과, 발견 위치, 수정했다면 저장본 재확인 |
| 4 | 공유 규칙의 검색 결과와 예외, 명령별 종료 코드·실제 결과, 렌더 확인 범위 |
| 5 | 최종 저장본 식별, 수정 전후 결과, 남은 오류·검사 한계·사람 확인 항목 |

단계 완료 보고만으로 다음 단계가 끝났다고 간주하지 않는다. 검사 실패가 있어도
독립적으로 수행할 수 있는 다른 검사와 나머지 문제 검토는 계속한다. 실행하지
못한 검사는 통과가 아니라 미실행으로 기록한다. 검토 전용 작업에서는 오류를
모두 보고하면 요청된 검토 작업을 마칠 수 있지만, 번역이 검증을 통과했다거나
승인 가능하다고 표시하지 않는다.

수정 후에는 이전 오류가 사라졌는지뿐 아니라 새 누락·수식 손상·데이터 변경이
생겼는지도 전체 대조한다. 의미를 확인하지 않은 자동 검사 결과만으로 배치를
완료 처리하지 않는다. 서브에이전트를 썼다면 부모가 저장본과 근거를 직접 확인한
뒤 최종 보고한다.

## 완료 보고 양식

아래 항목을 실제 결과로 채운다. 문제별 상세 근거는 `data/reports/`의 보고서에
둘 수 있으며, 사용자에게는 전체 결과와 확인이 필요한 사항을 모아서 전달한다.
보고 문장은 저장소의 대화 말투 지침을 따른다.

```text
대상 / 요청 범위: 문제 번호 목록 / 검토만 또는 검토·수정
검토한 저장본: 원문 SHA-256 / MDX SHA-256
발견 사항: 문제 번호 / 파일:행 / 규칙 파일·절 / 원문 근거 / 영향
수정 사항: 실제 바꾼 경로와 내용 / 수정 전후 검사 결과
검증: 명령별 종료 코드와 결과 / 렌더에서 실제 확인한 내용
수량 검색: 남은 일치와 각각의 비수량 근거 또는 0건
핵심 조건: 가장 헷갈리는 조건 / 대조한 예제·계산 근거
미해결: 원문 충돌 / 검사기 한계 / 미확정 이름 / 미실행 범위와 원인
사람 검수 참고: 실제 해석 불확실성이 있는 문구·이유; 확정 오류는 기계가 판정
검토 상태: 실제 상태 변경 여부 / 사람 승인 여부와 구분
```
