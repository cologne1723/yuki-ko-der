# 한국어 문제 번역 지침

## 적용 범위

- **적용-01 [필수]** 새 번역과 기존 번역의 수정에 이 지침을 적용한다. 원문의
  언어·문체나 기존 번역의 승인 여부를 규칙의 대체 기준으로 사용하지 않는다.
- **적용-02 [필수]** 원문의 의미와 실제 데이터를 보존하면서 이 문서의 문체·구성·표기를
  적용한다. 원문과 규칙을 동시에 만족시킬 수 없는 경우에는 충돌을 검토 기록에
  남긴다. 충돌이 해결되기 전에는 해당 항목을 준수 완료로 표시하지 않는다.
- **적용-03 [금지]** 이 지침을 승인된 번역의 수정이나 승인에 대한 새로운 권한으로
  해석하지 않는다. 승인된 문구의 수정에는 사용자의 명시적 요청이 필요하다.

## 요구 수준

요구 수준의 의미는 [RFC 2119 원문](https://www.rfc-editor.org/rfc/rfc2119.html)을
따른다. [한국어 번역본](https://techhtml.github.io/rfc/RFC2119.html)은 해석의
참고 자료이며, 차이가 있으면 원문을 기준으로 한다. 아래 한국어 표지는 이 문서에서
정의한 대응 표지이며 RFC가 지정한 공식 한국어 키워드는 아니다.

| 표지 | RFC 대응 용어 | 의미 |
| --- | --- | --- |
| 필수 | MUST / REQUIRED / SHALL | 반드시 준수해야 하는 요구 사항이다. |
| 금지 | MUST NOT / SHALL NOT | 허용하지 않는 행위이다. |
| 권고 | SHOULD / RECOMMENDED | 예외를 택할 타당한 이유가 있을 수 있으나, 전체 영향을 이해하고 신중히 판단해야 한다. |
| 비권고 | SHOULD NOT / NOT RECOMMENDED | 해당 행위를 정당화할 사유가 있을 수 있으나, 전체 영향을 이해하고 신중히 판단해야 한다. |
| 허용 | MAY / OPTIONAL | 선택적으로 적용할 수 있으며, 생략해도 위반이 아니다. |

- **규범-01 [필수]** 각 규칙은 고유 번호와 요구 수준으로 식별한다. 문체와 구성에
  관한 필수 규칙도 의미 보존 규칙과 동일하게 준수 여부를 확인한다.
- **규범-02 [금지]** 필수·금지 규칙에 명시하지 않은 예외를 취향이나 작업 편의를
  이유로 추가하지 않는다. 허용 규칙도 다른 필수·금지 규칙을 면제하지 않는다.
- **규범-03 [필수]** 권고에서 벗어나거나 비권고 행위를 선택할 때에는 사유와
  예상 영향을 검토 기록에 남긴다. 이는 자동으로 사용자 승인을 요구하는 절차는 아니다.

## 의미 보존

- **의미-01 [필수]** 문제 설명·정의·입력·제한·출력·공지·힌트·예제 설명 전체의
  의미를 보존한다. 조건, 예외, 가능성, 인과 관계, 부연 설명을 빠뜨리지 않는다.
- **의미-02 [필수]** 초기 상태, 동작의 순서와 횟수, 종료·승패 조건, 불가능한 경우,
  경계 포함 여부, 중복과 순서의 취급을 원문과 동일하게 전달한다.
- **의미-03 [필수]** 이야기, 인물의 성격, 농담, 대화와 역사적 시점의 설명을
  보존한다. 오래된 서술을 현재 사실로 갱신하여 원문의 시점을 바꾸지 않는다.
- **의미-04 [금지]** 원문에 없는 풀이, 알고리즘 힌트, 가정, 입력 조건을 추가하지 않는다.
- **의미-05 [허용]** 의미를 모두 보존하고 정보의 위치를 명확히 하는 경우 문장을
  통합·분리·재배치하거나 표·목록으로 변환할 수 있다. 의미가 중복되는 서술은 줄일 수 있다.
- **의미-06 [필수]** 번역 중 발견한 명백한 오타는 바로잡는다. 수식 오류도 원문의
  정의·조건·문맥으로부터 올바른 표현이 명백하게 결정되는 경우에는 바로잡고,
  수정 내용과 근거를 검토 기록에 남긴다. 오류 여부나 올바른 표현이 명백하지 않거나
  원문·예제 사이의 충돌을 해소할 수 없는 경우에는 임의로 수정하지 않고 문제 제작자에게
  질문을 남긴다. 질문에는 해당 원문, 의심되는 점과 근거를 포함하고, 답변을 받기 전까지
  미해결 사항으로 검토 기록에 남긴다.
- **의미-07 [금지]** 불명확한 충돌을 추측으로 해소하거나, 승인된 번역이라는 이유만으로
  원문과 모순되는 설명을 재사용하지 않는다.
- **의미-08 [필수]** 원문의 링크 대상과 이미지 데이터를 보존한다. 캡션과 링크 문구는
  한국어로 번역하되 해당 자료의 의미상 위치와 참조 관계를 유지한다.
- **의미-09 [금지]** 일본어 단어·구절 치환 스크립트로 번역문을 만들지 않는다.
  원문의 의미를 파악하여 한국어로 작성한다. 일본어는 문제에서 보존해야 하는
  데이터·인용·식별자·예제인 경우에만 남긴다.

## 문체와 용어

- **문체-01 [권고]** 설명 문장은 `합니다`체로 작성하고, 독자에게 요구하는 동작은
  `구하세요` 또는 `출력하세요`로 작성하는 것을 권고한다. 직접 인용·대화의 어조를
  보존하거나 문맥에 더 적합한 표현이 필요한 경우에는 다른 종결 표현을 사용할 수 있다.
- **문체-02 [필수]** 문제 안에서 동일한 대상·연산에는 동일한 용어를 사용한다.
  서로 다른 값이나 개념을 하나의 용어로 합쳐 구분을 잃지 않는다.
- **문체-03 [권고]** 대상의 식별 번호는 번호·`번`·명사의 순서로 쓴다.
  순서상 위치는 서수로 표현할 수 있으나 식별 번호와 혼동하지 않게 한다.
- **문체-04 [필수]** 한국어 조사·단위·의존 명사는 수식 밖에 쓴다. 조사는 앞말에
  붙이고, 의존 명사는 띄어 쓴다. 아라비아 숫자나 수식 값 뒤의 계수·측정 단위는
  붙여 쓴다. 번호의 어순을 바꿀 때에는 뒤따르는 조사도 고친다.
- **문체-05 [금지]** 번역문 본문에 작업 상태, 에이전트 말투, 임의의 접두 표식을
  추가하지 않는다. 기계 번역 표시는 저장 형식과 도구가 정한 방식만 사용한다.

## 문서 구성

- **구성-01 [권고]** 주요 절의 제목과 상대 순서는 `문제 설명`, `입력`, `제한`,
  `출력`, `예제`로 통일한다. 각 절은 두 번째 수준 Markdown 제목으로 작성한다.
  해당 내용이 없는 절은 생략하며, 빈 절을 만들지 않는다.
- **구성-02 [필수]** 원문에 별도로 존재하는 회고·공지·힌트는 의미상 위치와 참조
  관계를 유지하는 별도 절 또는 관련 절의 문단으로 보존한다. 이 보충 내용의
  위치는 구성-01의 주요 절 순서에 대한 예외로 한다.
- **구성-03 [필수]** 문단을 나누려면 빈 줄을 사용한다. 원시 HTML이나 실행 가능한
  MDX 구문으로 문단·목록·표·줄바꿈을 구현하지 않는다.
- **구성-04 [필수]** 게임·절차를 목록으로 작성할 때에는 실행 순서가 있는 항목과
  모든 단계에 적용되는 조건을 구분한다. 목록화 때문에 조건의 적용 범위가 바뀌면 안 된다.
- **공지-01 [필수]** 원문의 정정 공지와 수정 이력은 수정이 이미 반영되었거나 오래된
  내용이라는 이유로 생략하지 않는다. 공지 주체, 날짜·시각, 수정 대상과 내용, 독자가
  취해야 할 조치를 보존한다. 원문에 없는 시간대나 수정 사실을 추정하여 추가하지 않는다.
- **공지-02 [필수]** 원문에서 문제 설명보다 앞에 있는 출제자 공지는 번역에서도
  `## 문제 설명` 앞의 독립 문단으로 둔다. 여러 공지는 원문의 순서를 유지하며,
  문제의 이야기나 조건에 합치지 않는다.
- **공지-03 [권고]** 출제자 공지는 `(출제자 공지)`로 시작하고, 원문에 날짜·시각이
  있으면 이어서 표기한 뒤 공지 내용을 번역한다. 날짜·시각은 일반 텍스트로 유지한다.
  공지 전체를 수식이나 코드 블록으로 감싸지 않는다.

### 입력과 제한

- **입력-01 [필수]** 입력 형식은 언어 표지가 `text`인 코드 블록으로 작성한다.
  변수의 의미·자료형·배열 개수·구분 방식을 설명 또는 형식으로 명확히 전달한다.
- **입력-02 [허용]** 같은 문서에서 이미 정의했거나 입력 형식만으로 명확한 정보는
  반복 설명하지 않을 수 있다. 형식에서 알 수 없는 정보의 생략은 허용하지 않는다.
- **입력-03 [필수]** 여러 테스트 케이스는 개수 또는 종료 조건과 반복되는 형식을
  명시한다. 빈 문자열·빈 줄·공백 없는 문자열 등 입력 해석에 필요한 사항을 보존한다.
- **입력-04 [권고]** 설명용 입력 형식에서 같은 형식의 여러 행이 이어짐을 나타내며
  중간 행을 생략할 때에는 별도 행에 `$\vdots$`를 쓰는 것을 권고한다. 행 내부에서 항목이
  가로로 이어지는 생략 표시와 구분한다. 실제 예제 입력에는 이 규칙을 적용하지 않는다.
- **입력-05 [권고]** 개별 질의의 입력 형식도 `입력` 절의 `text` 코드 블록으로
  제시한다. 본문의 동작 설명에서 같은 형식을 다시 참조할 때에는 인라인 수식으로
  표현할 수 있다. 현재 표시 도구는 `입력`·`출력` 절 밖의 코드 블록을 실제 코드로
  취급하여 그 안의 수식을 렌더링하지 않으므로, 설명용 형식과 실제 코드를 구분한다.
- **제한-01 [권고]** 입력의 수치 범위는 `제한` 절에 모은다. 단일 수치 제한은
  목록 기호 없는 수식으로, 여러 제한은 항목별 목록으로 작성한다.
- **제한-02 [필수]** 동작을 정의하는 범위나 예외처럼 본문에 있어야 의미가 성립하는
  조건은 관련 문장 또는 문단의 끝에 둔다. 이는 제한-01의 이동 대상에서
  제외한다. 원문의 괄호가 부연 설명이나 코멘트를 구분하는 경우에는 문장 중간에
  있더라도 괄호와 그 내용을 유지한다.
- **제한-03 [필수]** 인덱스의 시작 값과 상한을 해당 배열·대상의 실제 개수와
  대조하여 명시한다. 서로 길이가 다른 배열에 같은 인덱스 범위를 일괄 적용하지 않는다.
- **제한-04 [권고]** 단독 제한에 장식용 괄호를 새로 추가하지 않는 것을 권고한다.
  원문의 괄호는 부연 설명이나 코멘트를 나타낼 수 있으므로 일괄 제거하지 않고
  유지하는 것을 권고한다. 수식 전체를 묶는 괄호는 같은 수식 안에 넣되, 자연어
  코멘트를 감싸는 괄호는 수식 밖에 둔다. 괄호 안의 의미 보존은 의미-01을,
  수학적 연산에 필요한 괄호 보존은 수식-03을 따른다.
- **제한-05 [허용]** 여러 조건은 각각 분리하거나 한 수식 안에서 세미콜론으로
  구분할 수 있다. 어느 방식이든 각 조건의 적용 대상을 명확히 한다.

### 출력과 예제

- **출력-01 [필수]** 출력할 값·단위·순서·구분자·줄 수·오차 허용 방식·실패 시 값을
  원문대로 전달한다. 원문에 있는 출력 끝 줄바꿈 요구도 명시한다.
- **예제-01 [필수]** 예제는 원문 순서대로 번호를 매긴다. 제목 문법은
  `### 예제 번호 {file="파일명"}`이다. `번호`는 순번으로 대체하고, `파일명`은
  원문 파일명을 JSON 문자열로 인코딩한다. 파일명이 없으면 `file=""`로 쓴다.
- **예제-02 [필수]** 각 예제의 실제 입력과 출력 앞에 각각 `#### 입력`, `#### 출력`을
  두고 `text` 코드 블록으로 담는다. 예제는 다음 예제 제목 또는 주요 절에서 끝난다.
  별도 닫기 표식은 사용하지 않는다.
- **예제-03 [필수]** 예제 설명의 경로·중간 상태·계산 과정·경우의 나열·결과의 이유·
  주의 사항을 모두 보존한다. 입력·출력 데이터가 보여 준다는 이유만으로 설명을 삭제하지 않는다.
- **예제-04 [금지]** 설명용 코드·도표·수열을 실제 예제 입력·출력으로 잘못 분류하여
  입력·출력 제목을 붙이지 않는다.

## 수식과 데이터

- **수식-01 [필수]** 수학적 값·변수·식·집합·수열은 TeX로
  작성하며, 구분자는 단일 달러 쌍 `$...$`만 사용한다. 이중 달러, `\(...\)`,
  `\[...\]` 구분자는 사용하지 않는다. 아라비아 숫자로 수량을 나타내는
  기수(cardinal)는 반드시 `$...$`로 감싼다. 실제 데이터와 프로그램 코드에는
  데이터-01과 데이터-02를 우선 적용한다.
- **수식-02 [권고]** 수식 안의 십진 정수는 오른쪽부터 세 자리마다 `\,`으로
  구분한다. 음수는 부호를 제외한 숫자에 적용한다. 쉼표나 일반 공백을 자릿수
  구분자로 쓰지 않는다. 소수와 식별자에는 이 변환을 적용하지 않는다.
- **수식-03 [필수]** 수식의 의미에 필요한 중괄호·첨자·부등호·구분자를 올바른
  TeX 문법으로 작성한다. 집합의 보이는 중괄호와 TeX의 그룹 문법을 구분한다.
- **수식-04 [필수]** 설명용 입력·출력 형식에서 수식으로 된 각 행은 단일 달러
  쌍으로 감싼다. 공백 구분 입력을 나타낼 때에는 TeX에서도 구분 간격이 표시되게 한다.
- **수식-05 [금지]** 문자 데이터·식별자·날짜·시각·버전·문서 제목의 번호·예제 번호·
  목록 순번을 수학적 값으로 간주해 자동 변환하지 않는다. 날짜 등의 값 자체가
  계산·제약의 대상인 경우에는 해당 수학적 표현에만 수식-01과 수식-02를 적용한다.
- **수식-06 [허용]** 아라비아 숫자로 순서나 순번을 나타내는 서수(ordinal)는
  `$...$`로 감싸도 되고 감싸지 않아도 된다. 다만 변수나 수식으로 표현한 순번에는 수식-01을 적용한다.
- **수식-07 [권고]** 수학적 값으로서의 수와 그 수의 표기에 쓰이는 숫자 문자를
  문맥에 따라 구분한다. 소수·계산값·수량은 수식으로, 자릿수의 문자 자체를
  가리키는 리터럴은 인라인 코드로 작성한다. 예를 들어 `소수 $5$`,
  ``숫자 `5`만으로 이루어진 수``, ``소수 $13$에 쓰인 숫자는 `1`과 `3` ``으로 쓴다.
  숫자를 나타내는 변수나 그 값의 범위는 `$A_i$`, `$0 \le A_i \le 9$`처럼
  수식으로 작성한다. 실제 예제 입력·출력과 프로그램 코드는 데이터-01과 데이터-02를 따른다.
- **수식-08 [권고]** 배열 수식의 행이 `+ `, `* `, `- `처럼 Markdown 목록으로
  해석될 수 있는 표기로 시작하면 수식 전체를 한 줄에 작성하는 것을 권고한다.
  수식 안의 행 구분은 TeX의 `\\`로 유지한다. 예를 들어 `array`의 첫 행이
  덧셈 기호로 시작하는 표는 소스 줄바꿈 때문에 목록으로 분리되지 않도록 한다.
- **데이터-01 [필수]** 실제 예제 입력·출력과 프로그램 코드의 내용을 문자 단위로
  보존한다. 선행·후행 공백, 빈 줄, 줄바꿈도 데이터에 포함한다.
- **데이터-02 [금지]** 실제 데이터·프로그램 코드에 번역, 수식 구분자 삽입,
  자릿수 구분, 공백 정리, 자동 서식 변경을 적용하지 않는다. 데이터-01과
  데이터-02는 일반 수식·문체 규칙보다 우선한다.
- **데이터-03 [필수]** 검토 시 실제 데이터, 프로그램 코드, 설명용 형식, 설명용
  수식을 구분한다. 원문의 예제 데이터가 기존 번역과 다르면 차이를 기록하고,
  기존 번역끼리의 일치만으로 보존 여부를 판정하지 않는다.
- **데이터-04 [허용]** 바이너리나 문자열 데이터를 다루지 않는 문제의 실제 예제
  입출력은 원문에 마지막 줄바꿈이 없어도 마지막 줄바꿈을 추가할 수 있다.
  이는 데이터-01과 데이터-02의 마지막 줄바꿈에 한정된 예외이다. 그 밖의 공백,
  빈 줄, 줄바꿈과 프로그램 코드는 이 예외의 대상이 아니다. 바이너리나 문자열
  데이터를 다루는 문제에는 이 예외를 적용하지 않는다.

## 검수

- **검수-01 [필수]** 원문 전체를 읽고 각 의미가 번역의 어느 문장·표·목록·형식에
  반영되었는지 확인한다. 특정 문제나 일부 문단만 대조해 문서 전체를 완료 처리하지 않는다.
- **검수-02 [필수]** 변수 정의·자료형·개수·범위·단위·동작·출력 요구·예제 설명을
  대조한다. 링크·이미지 누락과 식별 메타데이터의 변경 여부도 확인한다.
- **검수-03 [필수]** 변경한 번역의 컴파일, 수식 파싱과 표시, 데이터 보존을 검증한다.
  실제 예제와 프로그램 코드 영역을 제외하고 수식을 검사한다. 검사 도구가 확인하지
  못하는 의미·문체·구성 규칙은 별도로 검토한다.
- **검수-04 [금지]** 컴파일 성공이나 자동 검사 통과를 의미 보존 또는 사람의 승인으로
  간주하지 않는다. 변경한 한국어는 사람의 검수를 받아야 한다.
- **검수-05 [필수]** 작업 기록에는 적용한 규칙, 검토 범위, 검사 결과, 미해결 충돌과
  사람의 확인이 필요한 항목을 구분해 남긴다. 규칙을 개정한 경우 이전 검토 완료
  범위를 새 규칙까지 검증한 것으로 간주하지 않는다.
