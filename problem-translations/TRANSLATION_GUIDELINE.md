# 한국어 문제 번역 작업 지침

먼저 [공통 적용 원칙](00-policy.md)을 적용한다. 새 번역의 원문 유지 규칙을 기존 번역의 일본어 복원 지시로 해석하지 않는다. 수정 작업은 기존 저장본을 보존하며 허가 범위의 최소 패치로 진행한다.

이 문서는 전체 작업의 순서와 규칙 파일의 진입점이다. 규칙을 기억해서 적용하지
말고, 각 단계의 시작 직전에 지정된 파일을 다시 읽는다.

## 승인된 번역 보호 규칙

- 사람이 승인한 번역(`humanReview: true` 또는 비어 있지 않은 검수자 ID 목록)은 사용자가 해당 승인된 번역의 수정을 명시적으로 허용한 경우에만 수정한다. 일반적인 재검토·오류 수정·간결화·규칙 적용 요청을 승인된 번역의 수정 허가로 해석하지 않는다. 명백한 오류를 발견해도 허가 전에는 발견 사항과 구체적인 수정안을 보고할 뿐, 본문·수식·서식·이미지를 절대로 변경하지 않는다. `humanReview`를 삭제하거나 비워 이 제한을 우회하지 않으며, 승인 기록 변경도 사용자의 명시적 허가가 필요하다. 기존 대화에 해당 대상과 범위의 명시적 허가가 있으면 그 범위에서만 진행한다.

## 작업 순서

### 1. 원문과 메타데이터 확인

`01-source.md`를 읽고 원문 HTML 전체와 `index.json`의 정확한 `No`, `ProblemId`,
제목, 원문 해시를 확인한다.

### 2. 의미 초안 작성

`pnpm glossary -- data/problems-source/NUMBER.html`의 출력 항목만 읽은 뒤 `02-meaning.md`를
다시 읽는다. 원문의 이야기, 정의, 조건, 예외, 입력, 제한,
출력, 공지, 힌트, 예제 설명을 빠짐없이 한국어로 옮긴다.

### 3. 문서 구조와 수식 작성

`03-structure-and-format.md`를 다시 읽고 초안을 MDX로 구성한다. 특히 `입력`
절을 작성할 때 입력 형식 규칙을 다시 확인한다. 설명용 형식과 실제 예제 데이터는
절대로 같은 방식으로 작성하지 않는다.

### 4. 전체 대조와 자동 검사

`04-verification.md`를 다시 읽고 원문 전체와 번역 전체를 대조한 뒤 검증 명령을
실행한다. 자동 검사 통과는 사람 검토나 의미 보존을 뜻하지 않는다.

## 규칙 파일

- 원문·식별자: `01-source.md`
- 의미·번역체: `02-meaning.md`
- 반복 용어·고유명사: `glossary.yaml`을 사용하는 glossary 조회 명령
- 절 순서·입력/출력·수식·예제: `03-structure-and-format.md`
- 대조·자동 검사·검토 기록: `04-verification.md`

한국어 변경은 사람 검토가 필요하다. 새 번역은 `humanReview: []`와
`machineReview: unreviewed`를 유지하며, 검토 상태를 임의로 승인으로 바꾸지 않는다.
