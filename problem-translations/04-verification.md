# 전체 대조와 검증

초안이 끝난 뒤 이 파일을 다시 읽는다.

- 원문 HTML 전체와 번역 전체를 대조한다.
  첫 문제 설명 앞의 블록부터 확인한다. 시간 제한·출처·정정 공지는 메타데이터에
  같은 정보가 있어도 본문에서 생략하지 않는다. 각 원문 블록의 번역 위치를 찾는다.
  별도 `注記`의 확률·모듈러 정의도 블록으로 대조한다. 등장 변수와 합동식·유일성·표현 독립성 중 빠진 항목이 있으면 복원한다. 단순히 ‘법에서의 값’이라고 쓰는 것으로 정의를 대체하지 않는다.
  공지의 수량에도 수식 규칙을 적용한다. 예: `4000ms` → `$4\,000$ms`.
  방법: 원문 첫 블록의 첫 문장과 번역 대응 위치를 완료 보고에 명시한다. 제목이 같은 `문제문` 블록이 여러 개여도 앞 블록을 건너뛰지 않는다.
- 저장한 파일 자체를 다시 읽으며 본문 수식, `문제 설명` 제목, 예제 순번을 확인한다.
  방법: `rg -n '^## ' problem-translations/ko/problems/NUMBER.mdx`로 실제 제목을 나열한다. 대화형도 `문제 설명`을 생략하지 않으며, 출력할 질의·정답 형식은 출력 절에 한 번씩 둔다. 절 순서 검사 통과는 제목 존재나 중복 부재를 보장하지 않는다.
  TeX가 파싱돼도 `dots`나 `leq`가 평범한 문자로 해석되면 의미가 손상된 것이다.
  `rg -n --pcre2 '(?<!\\)\b(?:ldots|cdots|vdots|dots|le|ge|leq|geq|times|mathrm|left|right|frac|begin|end|pmod|bmod)\b' problem-translations/ko/problems/NUMBER.mdx`로 역슬래시 없는 명령을 찾고, 각 일치를 원문과 대조한다.
- 수식 옆에 코드 리터럴이 있으면 `$`를 닫은 뒤 백틱을 여는지 경계를 확인한다.
  방법: ``rg -n '`[^`]*\$[^`]*`' problem-translations/ko/problems/NUMBER.mdx``로 코드 안의 달러 기호를 찾는다. 변수·질의 형식·수치 답이면 백틱을 제거하고, 실제 문자열일 때만 유지한다. 코드 안의 수식은 렌더 검사에서 빠질 수 있다.
  ``rg -n '`-?[0-9]+`' problem-translations/ko/problems/NUMBER.mdx``로 인라인 코드 숫자도 찾는다. 본문·출력·예제 설명의 수치 답과 실패 값은 `$-1$`, `$5$`처럼 고친다. 실제 문자열·비트열만 코드로 유지한다.
  패치를 JavaScript로 전달할 때 TeX 역슬래시는 `String.raw`로 보존한다. 저장본에서 `\neq`가 줄바꿈+`eq`, `\vdots`가 제어문자로 바뀌지 않았는지도 원문과 대조한다.
  예: `$T_i=$` 다음에 코드 `(`를 둔다. 수식 안에 백틱을 넣거나 닫는 `$`를 빠뜨리지 않는다.
  렌더 결과에서도 변수는 수식으로, 괄호열은 원문 그대로 보이는지 확인한다.
  원문이 문자를 `\mathrm{m}`처럼 썼어도 리터럴 비교 규칙은 같다. 방법: `rg -n -F '\mathrm{' problem-translations/ko/problems/NUMBER.mdx`의 각 일치를 확인하고, 문자 비교라면 `$S_i=$` 뒤 인라인 코드 `m`으로 분리한다. 수학 연산자·단순 변수와 구별한다.
  문자 비교도 같다. 방법: 원문의 인라인 코드 문자를 저장본에서 찾아 `$S_{i,j}=$` 뒤 코드 `R`처럼 유지했는지 확인한다. `$S_{i,j}=R$`로 합치면 리터럴이 변수로 바뀐다.
- 원문의 도입과 첫 변수 정의를 각각 `원문 문장 → 저장 절`로 보고한다. 첫 문장이 번역되었다는 확인만으로 끝내지 않는다. 도입은 `이야기`, 변수 정의는 `문제 설명`인지 저장본에서 확인한다(별도 도입이 없으면 없음).
  `rg -n '하나|첫 줄|한 번|한 줄|한 면|한 자리|한 입력|한 파일|한 예|한 변|한 대|둘 다|두 |세 |네 |다섯 |여섯 |첫째|둘째|셋째|넷째|첫 번째|두 번째|세 번째|네 번째' problem-translations/ko/problems/NUMBER.mdx`를 실행한다.
  각 일치가 수량·순번이면 `$1$개`, `$2$줄`, `$1$번째`처럼 고친 뒤 재검색한다.
  일반 단어·실제 데이터는 바꾸지 않는다. 검색 없이 확인했다고 보고하지 않는다.
  명사 목록 밖의 수량도 `rg -n --pcre2 '(?<![가-힣])(한|두|세|네)\s+[가-힣]' 담당파일`로 찾는다. 예: ‘한 공원’ → ‘$1$개의 공원’. 일치가 수량인지 동사 ‘한’인지 문맥으로 구분하며 일괄 치환하지 않는다.
  ‘m→∞로 한 극한’의 ‘한’은 동사다. 검색을 0건으로 만들려고 ‘그’로 바꾸지 말고, 교정한 문장을 다시 읽어 동작·문법이 남았는지 확인한다.
  `두 수열`, `두 조건`, `첫째/둘째/셋째 줄`은 예외가 아니다. 각각 `$2$개의 수열`, `$2$가지 조건`, `$1$/$2$/$3$번째 줄`로 쓴다.
  `정확히 하나`, `적어도 하나`도 수량이다. 원문 표현이라는 이유로 예외 처리하지 않는다.
  `중 하나`도 선택 개수이므로 수량이다. `조건 1/2/3`처럼 본문에서 참조하는 순번도 수식으로 쓴다.
  완료 보고에는 마지막 저장 이후 실행한 이 검색의 실제 잔여 행과 예외 이유를 남긴다. 0건이면 `rg 종료 코드 1, 출력 없음`을 기록한다. 수정 전 검색이나 ‘확인함’이라는 요약으로 대신하지 않는다.
  예외 이유는 행의 다른 수식이 아니라 실제 일치 부분에 붙인다. 방법: `rg -n -o`로 일치 부분을 확인한다. `모두 $2$개`가 `두 `에 걸렸다면 예외는 ‘모두의 일부’이지 ‘$2$가 수식임’이 아니다.
  `카드 종류·입출력 행·예제 순번이라 확인함`은 예외 근거가 아니다. 남은 일치마다 실제 문구와 비수량인 이유를 적고, 수량이면 먼저 수정한다. 서브태스크 번호·배점은 예제 제목 예외가 아니다: `서브태스크 $1$: ($30$%)`처럼 쓴다.
  이야기·링크·예제 설명·입출력 설명의 평문 숫자도 `rg -n '[0-9](명|번|개|회|줄|차|자리|비트)|한 명' problem-translations/ko/problems/NUMBER.mdx`로 확인한다. 실제 데이터·제목 식별자는 제외한다.
  영문 단위도 `rg -n '[0-9](km|cm|mm|kg|ms|행|시)' problem-translations/ko/problems/NUMBER.mdx`로 찾는다. 방법: 일치가 실제 입출력 블록 안인지 먼저 확인한다. 예제 뒤 설명의 `시속 30km로 110km`는 데이터 예외가 아니라 `시속 $30$km로 $110$km`다. 자동 검사도 본문·강조문 안의 숫자+`km/cm/mm/kg/ms/행`을 검출하며, 코드·실제 예제·URL·이미지 속성은 제외한다.
  `집 2`, `선물 1`, `테스트 케이스 3`처럼 명사 뒤에 오는 대상 번호도 수식이다. 예제 설명의 대상 번호를 원문과 짝지어 확인한다. 방법: `rg -n '[가-힣] +[0-9]|[0-9]+[%점]|\*\*[0-9]+\*\*' problem-translations/ko/problems/NUMBER.mdx`로 표·배점·강조 숫자까지 찾고 각 일치를 확인한다. 제목 식별자만 제외한다. 본문 `테스트 케이스 3`은 자동 검사도 검출한다.
- 조건과 예제를 따라가서 부정·전체/존재·중복·경계 해석이 일치하는지 확인한다.
- 저장본의 동작 정의로 예제의 대상·중간 상태·종료 조건을 재현하고 원문과 비교한다. 원문만 계산해 답이 맞는 것은 번역 검증이 아니다. 예: ‘거리 C마다’의 대상 2,4,6은 ‘거리 C인 곳’으로 재현되지 않는다.
  예: `a=3, c=1`에서 `a←a-c`의 결과는 `2`다. 원문과 같아도 계산이 틀리면
  완료가 아니다. 기존 번역과 원문의 계산값이 다르면 바꾸기 전에 직접 계산한다.
  방법: 소수 오차 경계는 이진 부동소수점 대신 정확한 십진수로 빼고, 원문 오타를 되살리지 않는다. 수정 근거는 보고에 남긴다.
- 강조 목록에서 빠진 `**...**`는 Markdown 파싱을 확인한다. 방법: `**「이름」**이라는` → `「**이름**」이라는`, `**도시 $1$**에` → `**도시 $1$에**`. 닫는 `**` 앞 문장부호와 뒤 조사의 경계를 고친 뒤 목록을 다시 확인한다. 도구 한계로 단정하지 않는다.
- 원문 수식과 저장된 수식을 나란히 대조하고, 본문·제한의 네 자리 이상 정수와
  배열별 인덱스 범위를 별도로 확인한다. 예제 데이터의 숫자는 서식화하지 않는다.
  수식의 `\bm`·`\mathbf` 강조도 대응시킨다. 방법: 원문과 저장본에서 해당 명령을 검색한다. HTML 강조 목록은 TeX 강조를 세지 않는다.
  숫자 서식을 고칠 때 기존 수식 안에는 `$`를 추가하지 않는다. 예: `$N\leq 3000$` → `$N\leq 3\,000$`; `$N\leq $3\,000$`는 경계가 깨진 것이다.
  연쇄등식을 나눠 썼다면 각 항의 값을 원문의 마지막 값과 대조한다.
  예: `0 NAND 0 = 0 NAND 1 = 1`에서 두 연산의 값은 모두 `1`이다.
- 변수 정의, 자료형, 범위, 단위, 동작, 출력 줄 수·구분자·마지막 줄바꿈을 확인한다.
  방법: 원문에 있는 단위(예: `kg`, `cm`)를 저장본에서 검색해 수식 밖인지 확인한다. `\mathrm{kg}`처럼 TeX가 유효해도 단위를 수식 안에 두지 않는다.
  반복 누락된 시간·메모리 단위는 `rg -n 'ms|MB|GB' 담당파일`로 공지까지 찾고, 각 단위 바로 앞에서 `$`가 닫혔는지 확인한다. `\text`·`\mathrm` 렌더 통과는 단위 규칙 통과가 아니다.
  ‘입력은 모두 정수’ 같은 전체 단정은 각 입력 행의 변수 정의·예제와 대조한다.
  문자열이 섞여 있으면 해당 단정을 추가하지 말고, 원문에도 있으면 충돌을 확인한다.
- 입력 형식을 원문과 행별로 대응시켜 첫 행·생략 표시·마지막 행을 확인한다.
  입력·출력의 설명용 형식 블록을 각각 행별로 대조한다. 생략 표시 앞의 명시 행은 변수 이름과 무관하게 보존한다. 예: `A_2 B_2`, `u_2 v_2`, `H_2`. 문장으로 설명했어도 원문 형식 블록을 삭제하지 않는다.
  같은 행의 명시 항도 보존한다. 원문의 `w_1 w_2 ... w_n`을 `w_1 ... w_n`으로 줄이지 않는다. 방법: 원문 출력 절의 각 형식 블록을 저장본과 하나씩 짝짓는다. `$M$` 한 줄이나 `Yes`/`No` 분기 블록도 설명 문장으로 대체하지 않는다.
  여러 대상을 옮기거나 고르는 동작은 대상별 선택인지 일괄 선택인지 예제와 대조한다.
- 설명용 형식의 변수에 `$...$`가 있는지 확인한다. 실제 예제의 `$`를 포함한 모든
  문자는 원문과 대조하여 보존한다.
  리터럴을 수식으로 만든 반복 오류도 찾는다. 방법: `rg -n '^\$(Yes|No)\$$' 담당파일`의 각 행을 원문 출력 형식과 대조하고, 실제 문자열이면 달러를 제거한다. 자동 검사 통과로 이 대조를 대신하지 않는다.
  대안 출력까지 각 실제 데이터 블록마다 `#### 입력`/`#### 출력`이 있는지 확인한다. 앞 블록의 제목을 재사용하지 않는다. 데이터 검사 통과는 제목 존재를 보장하지 않는다.
  방법: 대안 출력마다 `원문 값 → 저장본의 개별 제목 행`을 보고한다. 설명용 PRE는 이 목록에서 제외한다.
  제출 코드·변환 전 예시를 실제 입력으로 표시하지 않는다. 방법: 각 블록 직전 원문에서 '제출한다'와 '입력으로 주어진다'를 구분한다. 검사기가 설명 코드를 입력으로 오인하면 제목을 추가하지 말고 검사 한계로 보고한다.
- 본문 속 괄호열·비트열 예시도 데이터다. 원문에서 추출한 문자열과 저장본을
  문자 단위로 비교한다. 괄호가 균형을 이루거나 예제 입출력 검사가 통과해도 충분하지 않다.
  격자 예시도 각 행을 비교한다. `#.#`와 `.#.`는 다른 데이터다. 예제 설명의 행도 원문에서 복사하고, 수식 안에 옮기며 재작성하지 않는다.
  문자열 치환 문제의 중간 문자열도 포함한다. 직접 재타이핑하지 말고 원문에서 복사한 뒤 치환을 실행해 대조한다.
  반대로 예제 설명의 변수 등식·계산 결과는 실제 입출력이 아니다. 원문 수식을 인라인 코드로 바꾸어 수식·정수 서식 검사를 피하지 않는다.
- 예제 비교 시 마지막 줄바꿈 하나의 유무는 무시한다. 그 차이는 오류로 보고하지 않는다.
- 원문의 표·빈 제목에 있는 실제 입출력도 순서대로 보존한다. 검사기가 이를
  인식하지 못하면 한계로 보고한다. 통과하려고 출력 제목을 바꾸거나 코드 블록을
  삭제하지 않는다. 출력 데이터인 마지막 빈 줄은 마지막 줄바꿈 하나와 다르다.
  대화형 예제는 표의 각 입출력 셀을 시간순 블록으로 옮기고 사이 설명도 대응시킨다. Markdown 표가 보존 검사를 통과해도 이 형식 규칙의 예외가 아니다. 방법: 저장본의 각 데이터 셀에 대응하는 `#### 입력`/`#### 출력`과 `text` 블록을 센다.
  입력끼리·출력끼리 합치지 않는다. 원문 셀 수와 번역 블록 수를 직접 세어 확인한다. 각 셀의 원문 열 제목도 대조한다. 방법: 프로그램의 질의·정답은 출력, 채점기의 응답은 입력인지 확인한다. 데이터 순서·개수 일치만으로 방향 보존을 판단하지 않는다.
- 조회 명령이 출력한 항목의 `forbidden` 표기가 번역문에 없는지 확인하고, 표준 표기를
  사용했는지 확인한다.
- 실행 코드는 원문 코드와 직접 대조한다. 검사기가 코드의 정규식·달러 기호를 수식으로 오인해도 코드를 바꿔 우회하지 않는다.
- 링크, 이미지, 식별 메타데이터, 예제 파일명을 확인한다. 각 이미지 앞뒤 원문 텍스트를
  번역의 같은 위치와 대조한다. 이미지가 모두 남아도 정례·반례 전환문이 빠지면 의미가 뒤집힌다.
  base64 이미지는 MDX에 남아 있지 않은지, 참조 파일이 존재하고 원문 디코딩 결과와 일치하는지 확인한다. 실제 미리보기에서도 이미지를 연다. 로컬 경로가 원문 사이트 URL로 바뀌거나 검사기가 파일 참조를 지원하지 않으면 완료로 처리하지 말고 지원 누락을 보고한다.
- `sourceTitle`은 원문 그대로, `title`은 번역 제목인지 따로 확인한다.
  제목에 수식이 있으면 저장된 `title`의 여는·닫는 `$`와 렌더 결과를 별도로 확인한다. 본문 검사 통과로 제목 수식 검증을 대신하지 않는다.
  원문 제목의 괄호 안 언어·버전 식별자도 대응시킨다. `(C++)`, `(Python)`은 번역 제목에서 삭제하지 않는다.
  `Easy/Normal/Hard` 같은 일반 난이도 표시는 고유명사가 아니다.
  제목 용어를 이야기와 본문의 정의·연산에 대조한다. 다의어는 사전의 첫 뜻으로 교체하지 않는다. 예: 두 합을 곱하는 `Multiple`은 ‘곱’, 틈새바람을 도입에 언급한 `Draft`는 ‘틈새바람’이다.
- 미해결 충돌과 사람 확인 항목을 별도로 기록한다.
  원문 유지한 이름은 원문에서 이름+호칭 전체를 복사해 저장본에서 검색한다. 일부 음역·로마자화·호칭 번역이 있으면 복원한 뒤 보고한다.
  방법: 미확정 이름마다 `원문 전체 → rg -n -F 실제 저장 행`을 제시한다. 뜻풀이 번역도 원문 유지가 아니며, 0건이면 미완료다.
  라틴 문자 이름도 같다. `Alice さん`을 `Alice`로 줄이는 호칭 삭제도 누락이므로, 원문에서 호칭을 먼저 찾아 glossary 대응 없는 전체 이름을 대조한다.
- 완료 보고에는 실제 확인한 항목만 쓴다. 단순 컴파일 결과로 "의미 충돌 없음"을 선언하지 않는다.
  독립 계산을 실행했다고 보고할 때는 재현 가능한 명령 또는 스크립트 경로와 실제 출력도 제시한다. 답과 직전값만 계산했으면 전역 최소성을 확인했다고 쓰지 않는다.
  후보 제한·단조성을 가정한 계산은 조건부 검산이다. 방법: 전수 탐색이 아닌 경우 생략한 후보를 제외하는 근거와 탐색 전제를 제시한다. ‘귀납하면 성립’이라는 주장이나 예제 일치만으로 증명했다고 보고하지 않는다.
  검증 계산·보존 근거·편집 메모는 완료 보고에만 쓴다. 원문에 없는 설명을 번역 MDX에 추가하지 않는다.
  부모가 전달한 계산 근거·참고 링크도 원문이 아니다. 방법: 추가한 설명마다 원문 대응 문단을 찾고, 없으면 본문에서 빼고 보고에만 남긴다.
- 완료 보고에 가장 오해하기 쉬운 조건과 이를 대조한 예제 근거를 한 줄 남긴다.

검증 명령은 다음 순서로 실행한다.

```sh
git diff --check
pnpm validate:problems --problems NUMBER
pnpm lint:problems --problems NUMBER
pnpm check:translation -- --require-unreviewed NUMBER
```

마지막 명령은 입출력 코드 블록의 `text` 표지·주요 절 순서·예제 데이터·파일명·이미지·링크·원문 해시·glossary 표기·집합 포함 수식·정수 서식·KaTeX
렌더링을 검사한다. 실패하면 수정 후 재실행하고, 의도적 수식 변경으로 대응이
안 되면 완료 대신 충돌을 보고한다. 의미 전체를 판정하는 검사는 아니다.
`첫째`, `두 번째`, `한 번`, `하나 이상` 등 반복된 수량 누락도 실패시킨다. 검출 범위는 제한적이므로 위의 전체 검색을 대체하지 않는다.
반복 누락된 ‘두 정수·두 다중집합·두 이동 방법·한 방향·한 방법·한 칸·한 공원’도 자동 검출한다. 새 명사 전체를 보장하지 않으므로 일반 명사 수량 검색은 계속 실행한다.
수식으로 명시된 입출력 형식의 행 수 감소도 검사한다. 대안 형식을 한 블록에 모으는 것은 허용하며, 행 내용·리터럴 형식까지 판정하지 않으므로 행별 대조는 유지한다.
`A_0` 또는 `A_1`이 명시된 변수군은 `A_2` 같은 숫자 첨자의 누락도 검사한다. 고립된 첨자·문자 첨자·순서까지 보장하지 않으며, 원문 오타를 되살려 통과시키지 않는다.
`git diff --check`는 저장소 루트에서 경로 인수 없이 실행한다. 범위 밖 오류는 경로·종료 코드와 함께 보고하고, 경로를 제한한 재검사를 전체 통과로 바꾸어 보고하지 않는다. 미추적 파일은 검사하지 않으므로 신규 파일의 검증 근거로 삼지 않는다.
Prettier는 `.prettierignore`에서 번역 디렉터리를 제외한다. 실행 성공을 번역 검사 통과로 보고하지 않는다.

번역 작업에서는 위의 미승인 강제 옵션을 생략하지 않는다. 승인된 기존 파일이 걸리면 상태를 임의로 바꿔 통과시키지 말고 배정 범위를 확인한다. 별도 검토 작업은 검토 워크플로를 따른다.

자동 검사 통과는 의미 보존이나 사람 검토를 뜻하지 않는다. 새 번역은
`humanReview: []`, `machineReview: unreviewed`를 유지한다.
