# 문서 구조와 서식

MDX를 작성하기 직전에 반드시 이 파일을 다시 읽는다.

## 절 순서

먼저 `문제 설명`, `입력`, `제한`, `출력`, `예제` 순서의 빈 골격을 만들고 내용을
해당 절에 채운다. 원문 절 순서를 그대로 복사하지 않는다. 원문 앞의
공지는 문제 설명 앞에 둔다. 문단은 빈 줄로 나누며 원문의 공지·힌트·회고·예제
설명을 생략하지 않는다.
초안 완료 전 원문 `img` 수와 저장본 이미지 수를 비교한다. 접힌 `문제 비주얼` 안의 장식 표지도 생략하지 않고 원문 위치에 복사한다.

실제 제목은 `## 문제 설명`이다. `## 문제`로 줄이지 않는다. 원문에 별도 이야기가
있으면 `## 이야기`로 먼저 두고, 정의와 동작은 `## 문제 설명`에 둔다. 방법: 첫 변수 정의 앞의 동기·도입 문장을 찾으면 골격에 `## 이야기`를 먼저 추가한다. 저장 후 그 문장과 첫 변수 정의의 소속 절을 각각 확인한다. 같은 원문 문단·`問題文` 블록 안에 있어도 분리한다.
내용이 없는 절은 만들지 않는다. 공지의 날짜·시각·정정 내용은 보존한다.
본문의 `b`·`strong`·`u` 강조는 대응 문장을 `**...**`로 보존한다. 방법: 저장 후 `node --import tsx tools/show-problem-emphasis.mjs NUMBER`로 목록을 뽑아 각 항목을 제목/조건으로 분류하고 의미별로 짝짓는다. `<strong>制約</strong>`는 `## 제한`에 대응하므로 `**제한**`을 중복 추가하지 않는다. 반면 본문·제한에 반복된 조건 강조는 각각 보존한다. 목록 개수 일치는 통과 근거가 아니며 원시 HTML은 추가하지 않는다.
수학적 목표 요약은 `문제 설명` 첫머리에 둔다. 방법: `概要`에 이미 `S가 주어집니다`가 있으면 그 `S`가 첫 변수다. 수학적 배경은 대상·구할 값 정의 뒤 `### 배경`으로 두며 이야기를 만들지 않는다.
강조 목록은 `code` 안의 강조를 누락할 수 있다. 방법: 원문 `code strong`도 직접 추출하여 `**`로 감싼 코드 조각으로 보존하고, 조각을 이어 붙인 문자열이 원문과 같은지 비교한다.

부분점 표는 제한 절에 둔다. 방법: 원문과 저장본의 각 행을 `이름·배점·조건`으로 짝짓는다. 전체 제한 목록은 부분점 표의 대응이 아니다. 예제의 부분문제 번호도 해당 조건에 대입한다. `10%（30点）`는 `$10$% ($30$점)`이며 ‘또는’을 추가하지 않는다.

## 이미지 파일

- 인라인 `data:image/...;base64,...`는 디코딩하여 `ko/images/{problemNo}/{순번}.{확장자}`에 저장한다. 확장자는 원문 MIME 형식에 맞추며 재인코딩하지 않는다.
- MDX에는 base64 대신 `![대체 텍스트](../images/{problemNo}/{순번}.{확장자})`로 참조한다. 실행 가능한 `import` 구문은 쓰지 않는다. 원문 위치·개수·대체 텍스트의 의미를 보존한다.
- 이미지가 검게만 보이면 흰 배경의 로컬 미리보기에서 다시 확인한다. 일본어 설명·표 라벨이 있으면 원본 이미지는 유지하고 옆에 한국어 대응을 적는다. 이미지 보존을 번역 완료로 간주하거나 표의 수치·정답을 재작성하지 않는다.
- base64 본문을 에이전트 메시지나 터미널 출력에 복사하지 않는다. 원문 파일에서 직접 추출한다. 이미지 파일 생성은 담당 문제의 수정 범위에 포함한다.
  방법: 원문 이미지를 포함한 초안을 저장한 뒤 `node --import tsx tools/audit/src/extract-problem-images.ts NUMBER`를 실행한다. 이 명령이 파일 분리와 MDX 참조 치환을 수행한다. 기존 파일 충돌·지원하지 않는 형식은 덮어쓰거나 생략하지 말고 보고한다.

## 입력·출력 형식

- 설명용 형식은 언어 표지가 `text`인 코드 블록으로 작성한다.
- 설명용 형식의 각 행 전체를 단일 `$...$`로 감싼다. `$A$ $B$`가 아니라 `$A\ B$`다.
  대화형 변수 행도 `$?\ i\ j$`, `$!\ X$`처럼 접두 기호까지 감싼다. `! $X$`는 틀리며, 변수가 없는 실제 리터럴 `! NaN`은 그대로 둔다.
- 설명용 입력 형식은 `$N$`, `$A_1\ \cdots\ A_N$`처럼 작성한다.
- `Yes`/`No`만 있는 행은 리터럴이다. 원문에 없는 `$Yes$`/`$No$`로 바꾸지 않는다.
- `N`, `A_1 ... A_N`처럼 변수를 평문으로 쓰지 않는다.
- 본문에서 다시 언급하는 질의 형식도 수식이다. 변수 포함 형식을 실제 문자열처럼 인라인 코드로 쓰지 않는다.
- `$$...$$`, `\(...\)`, `\[...\]`는 사용하지 않는다.
- 설명용 형식에는 변수의 의미·자료형·개수·구분 방식을 문장으로 명시한다.
- 이미 정의했거나 형식만으로 명확한 설명은 반복하지 않는다. 여러 테스트 케이스의
  개수·종료 조건, 문자열의 공백·빈 줄 조건은 생략하지 않는다.
  원문의 테스트별 변수 대응도 보존한다. 방법: 본문의 `N`과 입력의 `N_t`처럼 표기가 달라지면, `t번째 문제의 N을 N_t로 나타낸다`는 정의가 있는지 확인한다.
- 여러 행을 생략할 때는 별도 행의 `$\vdots$`를 사용한다. 입력으로 받는 개별 질의 형식은 입력 절에, 대화형에서 프로그램이 출력하는 질의·정답 형식은 출력 절에 둔다. 방법: 원문 절 제목이 아니라 각 형식 직전 문장의 송신 주체로 분류한다. 채점기 응답은 원문의 `出力` 절에 있어도 응답 설명과 함께 입력 절로 옮기며, 두 절에 중복하지 않는다.
  원문이 명시한 토큰은 생략 표시로 줄이지 않는다. 원문 `A_1 A_2 … A_N`은
  `$A_1\ A_2\ \cdots\ A_N$`이며, `A_2`를 삭제하지 않는다.
- 수치 제한은 제한 절에 모으되 동작을 정의하는 조건은 관련 본문에 남긴다.
  출력 값·순서·구분자·줄 수·오차 허용·실패 시 값·마지막 줄바꿈 요구를 보존한다.
- 실제 예제 입력·출력은 원문을 보존하되, 마지막 줄바꿈 하나의 유무는 허용한다.
  추가 빈 줄, 줄 안의 공백, 데이터 문자 변경은 허용하지 않는다.
  반복 출력도 손으로 재작성하지 않는다. 방법: 원문 PRE를 `samplePreText`로 추출해 패치에 넣고 저장본과 직접 비교한다. `N=100`이라는 설명이나 눈대중으로 줄 수를 대신 확인하지 않는다.

## 수식·예제

- 수학적 값·변수·식은 단일 `$...$`로 작성한다. 실제 데이터와 코드는 예외다.
  출력 설명의 실패 값도 `$-1$`로 쓴다. 실제 예제의 `-1`은 그대로 둔다.
- 본문의 수량도 `$1$분`, `$2$개`처럼 쓴다. 수식 안의 십진 정수는 `10\,000`처럼
  세 자리씩 구분한다. 날짜·식별자·예제 번호에는 적용하지 않는다.
  이진수 등 다른 진법의 숫자열에는 십진수 자리 구분을 적용하지 않는다.
  예: `1100_{(2)}`는 그대로 둔다. 검사기가 이를 십진수로 오인하면 한계를 보고한다.
- 조사·단위는 수식 밖에 둔다. 보이는 집합 괄호는 `$\{a,b\}$`로 쓴다.
  방법: 원문의 `$x\%$`도 `$x$%`로 옮기고, 저장본의 `%`를 검색해 본문·예제 설명 모두 확인한다.
  TeX의 `~`는 공백이다. `32 ~ \mathrm{bit}`를 범위 기호로 바꾸지 말고 `$32$비트`로 옮긴다.
- 파일을 저장한 뒤 반드시 다시 읽는다. `\dots`, `\ldots`, `\leq`, `\times`의
  역슬래시가 남았는지 확인한다. `$dots$`, `$1leq ileq N$`, `${a,b}$`는 잘못된 결과다.
  도구 호출 문자열에서 역슬래시가 이스케이프될 수 있으므로 저장 전 문자열만 믿지 않는다.
  JavaScript 패치는 일반 문자열이 아닌 `String.raw`로 만든다. 백틱 코드 펜스는
  별도 문자열로 이어 붙이고 `${` 보간을 피한다. 셸로 TeX를 조립하지 않는다.
  저장본의 코드 펜스는 역슬래시 없는 백틱 3개여야 한다. `String.raw` 안에서
  백틱을 이스케이프하면 역슬래시까지 저장되므로, 펜스는 `'```text'`처럼 따로 만든다.
- 원문 수식을 불필요하게 다시 쓰지 않는다. 집합·경우 나누기 수식은 원문 TeX를
  보존한다. `{...}` 일괄 치환은 첨자·분수까지 망가뜨리므로 금지한다.
- 인덱스의 시작·끝을 실제 배열 개수와 대조한다.
- 예제 제목은 `### 예제 1 {file="sample.txt"}`처럼 실제 순번으로 쓴다.
  `예제 번호 1`이라고 쓰지 않는다. 파일명은 원문 값이며 없으면 `file=""`이다.
  원문 HTML의 잘못된 중첩과 무관하게 각 예제는 같은 깊이의 독립된 제목이다. 검사 통과를 위해 예제 2를 예제 1 안의 `####` 제목으로 내리거나 `file` 속성을 삭제하지 않는다.
- 예제의 실제 입력·출력에만 해당 제목과 `text` 코드 블록을 둔다.
  제목은 `#### 입력`, `#### 출력`이다. `입력:`, `출력:` 문단으로 대체하지 않는다.
  출력 전용 예제에는 빈 입력 블록을 만들지 않는다. 오답 예시는 오답이라는 설명을 유지한다.
- 예제의 풀이 과정·단계 설명은 번역한 문단이나 목록으로 둔다. 원문의 `<pre>`라고
  모두 실제 입출력 데이터인 것은 아니다. 설명 수식을 데이터 코드 블록에 숨기지 않는다.
- import, export, JSX, 실행 표현식, 구조용 원시 HTML, `<br>`를 사용하지 않는다.
