# 의미 보존과 한국어 문체

초안을 작성하기 직전에 이 파일을 다시 읽는다.

[공통 적용 원칙](00-policy.md)을 먼저 적용한다. 기존 문서 검토에서는 새로운 음역을 만드는 일과 기존 표기를 보존하는 일을 구분한다.

`pnpm glossary -- data/problems-source/NUMBER.html`을 실행하고 출력된 항목만 읽는다.
출력이 없으면 조회된 glossary 항목이 없다는 뜻이다. 사용자 확정 지시가 없거나 기존 표기가 틀렸다는 뜻이 아니다. 번역 작업에서 glossary 전체를 열지 않는다.
사용자 확정 지시를 우선 적용한 뒤 출력된 표준 표기·금지 표기와 대조한다. 충돌하면 확정 표기를 유지하고 glossary 불일치를 보고한다.

## 간결하게 작성하기 — 필수

- 원문의 정보는 빠짐없이, 한국어 문장은 간결하게 쓴다. 같은 내용을 다른 말로 반복하거나 입력 형식을 줄별로 풀어 늘어놓지 않는다.
- 본문에서 정의한 변수와 형식만으로 분명한 행 수·순서·공백 구분은 입력 절에서 재설명하지 않는다. 변수의 뜻이 아직 없거나 공백 없는 문자열·종료 조건처럼 형식만으로 알 수 없는 정보만 보충한다.
- 정수 입력은 원칙적으로 제한 절에 명시한다. 본문·입력 설명에서 모든 대상의 정수성이 정말 명백한 경우에만 별도 문장을 생략한다. 예: 이미 정수·자연수라고 명시했거나 모든 대상이 개수·번호인 경우다. 체력·시간·거리·무게·레벨 같은 의미나 정수인 상·하한만으로 명백하다고 판단하지 않는다. 생략해도 되는지 애매하면 명시하는 쪽을 택한다. 단, 실제로 정수 입력인지 불확실하거나 원문과 충돌하면 임의로 정수 조건을 만들지 말고 근거를 확인·보고한다.
- 입력 변수가 여러 개이고 모두 정수라면 제한 절에 정확히 `- 입력으로 주어지는 모든 수는 정수입니다.`라고 한 번 쓴다. 5·6·9번을 이 문구의 기준으로 삼는다. 입력 변수가 하나면 `- $N$은 정수입니다.`처럼 해당 변수만 지정한다. 문자열·실수 등이 섞이면 정수인 변수만 지정한다. 변수마다 `정수`, `양의 정수`를 반복하지 않으며, 양수 여부는 범위로 충분하면 반복하지 않는다. 변수 정의의 중복 설명을 생략하더라도 필요한 정수 조건은 보존한다.
- 답 하나를 뜻하는 임시 이름 `Ans`는 출력할 값이 문장으로 명확하면 생략한다. 이름을 보존하려고 원문에 없는 출력 형식 블록을 만들지 않는다. 실제 출력 순서·여러 값의 관계·프로토콜에 필요한 이름과 형식은 보존한다.
- 사람 수정에서 기준을 배울 때는 **원문 → 수정 전 번역 → 사람이 수정한 번역**을 함께 대조한다. 무엇을 삭제·통합·복원했는지 확인하고 적용한다. 수정 후 문장만 보고 취향을 추정하지 않는다. 기존 규칙과 예외를 먼저 확인하고, 이미 허용된 선택을 새 예외나 위반으로 분류하지 않는다.
- 예: 33번의 변수마다 붙인 정수 설명은 제한 절의 한 문장으로 모으고, 34·54번의 중복 입력 설명은 되살리지 않는다. 38·52번의 단일 답 `Ans`를 위한 추가 블록도 만들지 않는다. 51번의 `W/D^2`는 사람이 원문의 `\frac{W}{D^2}`를 복원한 것이므로 임의의 수식 재작성 사례로 분류하지 않는다.
- 간결화 후에도 변수 정의, 선택 범위, 반복·종료 조건, 예외와 예제의 의미를 대조한다. 필요한 조건을 삭제하거나 문장을 미완성으로 남기는 것은 간결화가 아니다.

## 문장과 정의 — 필수·권장

아래의 **필수**는 의미를 명확히 전달하기 위한 기준이고, **권장**은 문맥에 따라 선택하는 작성 방법이다. 권장과 다르다는 이유만으로 기존의 동등한 표현을 오류로 판정하지 않는다. [UCPC 참고 근거와 적용 범위](#ucpc-참고-근거와-적용-범위)를 함께 적용한다.

- **필수:** 대상·변수·연산·구할 값의 뜻이 문서 안에서 명확해야 한다. 원문에 있는 정의를 보존하고, 지시어가 여러 대상을 가리킬 수 있으면 해당 대상을 밝혀 쓴다. 원문 자체가 불명확하면 정의나 가정을 만들어 보충하지 말고 보고한다. 입력 변수의 설명 위치와 중복 생략은 위의 간결성 규칙을 따른다.
- **권장:** 한 문장에 정의·동작·예외를 겹쳐 쓰기보다 의미 단위로 나누고, 같은 대상을 설명하는 문장끼리 문단을 구성한다. 문장을 나눌 때 조건의 적용 범위와 인과관계를 유지한다.
- **권장:** 긴 부연 설명은 괄호 안에 넣기보다 독립 문장으로 쓴다. 순서쌍·구간·수식의 괄호와 짧고 명확한 부연은 그대로 쓸 수 있다. 원문의 이야기·공지·힌트를 괄호 문장이라는 이유로 삭제하지 않는다.
- **필수:** 정수 범위에서 $0$의 포함 여부가 명확해야 한다. 새 번역은 원문 근거에 따라 ‘양의 정수’·‘음이 아닌 정수’ 또는 정수 조건과 부등식으로 표현한다. 정수 조건과 범위가 이미 충분하면 같은 뜻을 반복하지 않는다. 기존의 ‘자연수’도 범위가 명확하면 일괄 오류로 취급하지 않으며, 원문으로 범위를 확정할 수 없으면 추측하지 않는다.
- **필수:** 정의를 설명하는 원문의 짧은 예시와 정식 예제 입출력을 구분한다. 정의에 붙은 예시는 관련 본문에 보존하고, 예제 절로 일괄 이동하지 않는다. 이해를 돕는다는 이유로 새 예제·그림·풀이를 추가하지 않는다.

다음은 이 지침을 위해 만든 작성 예시다. 실제 번역에서는 원문에 있는 정보에만 적용한다.

| 상황 | 작성 전 | 작성 예시 |
| --- | --- | --- |
| 복문 분리 — 권장 | 길이가 $N$인 수열 $A$가 주어지고 각 원소를 최대 한 번 선택할 수 있으며 선택한 원소의 합을 최대화해야 합니다. | 길이가 $N$인 수열 $A$가 주어집니다. 각 원소는 최대 한 번 선택할 수 있습니다. 선택한 원소의 합의 최댓값을 구하세요. |
| 부연 괄호 분리 — 권장 | 정점 하나를 선택합니다(선택한 정점은 다시 선택할 수 없습니다). | 정점 하나를 선택합니다. 한 번 선택한 정점은 다시 선택할 수 없습니다. |
| $0$ 포함 여부 명확화 — 필수 | 자연수 $K$를 선택합니다. | 원문에서 $0$을 허용하는 정수임이 확인되었다면 ‘음이 아닌 정수 $K$를 선택합니다.’로 씁니다. 이미 정수 조건과 $K \ge 0$이 명시되어 있으면 반복하지 않습니다. |

## 의미와 표현

- 원문에 없는 풀이, 힌트, 가정, 조건을 추가하지 않는다.
- 조건, 예외, 순서, 횟수, 경계, 종료·승패 조건을 빠뜨리지 않는다.
  방법: `またそのときに限り`·`必要十分`은 ‘그때에만’·‘필요충분’으로 대응시킨다. 반복 조건을 공통 문장으로 합쳐도 양방향 조건을 단순 ‘이면 가능’으로 줄이지 않는다.
- 여러 대상의 선택은 `각각 선택한다`와 `모두 같은 것을 선택한다`를 구분해 쓴다.
  `모든 대상을 ... 중 하나로`처럼 둘 다 가능한 문장은 예제로 뜻을 확정해 고친다.
  방법: 문자 종류 제한은 `각 문자가 ... 중 $1$개인 문자열`로 쓴다. `중 $1$개로 이루어진 문자열`로 바꾸면 단일 문자 반복으로 읽힌다. 연산자 인접 금지는 `연산자끼리는 인접하지 않는다`이며 `$1$개끼리`가 아니다.
  수량 서식 교정도 논리 범위를 보존한다. 방법: ‘원소 중 어느 것의 배수’는 ‘적어도 $1$개 원소의 배수’이지 ‘정확히 $1$개’가 아니다. 겹치는 배수가 있는 예제로 확인한다.
- 부정문의 범위를 구분한다. "아무도 모른다"와 "전원을 아는 것은 아니다"는 다르다.
  앞뒤 정의와 예제를 실제로 따라가며 해석을 검증한다. 문맥으로 확정되면 근거를 기록하고,
  확정되지 않으면 충돌을 보고한다. 한국어로 옮기기만 하고 모순을 방치하지 않는다.
- 이야기, 인물, 대화, 공지, 예제 설명을 보존한다.
- 링크 대상·이미지·프로그램 코드도 보존한다. 중복 설명은 합칠 수 있지만 정보는 빠뜨리지 않는다.
- 같은 대상과 연산에는 문서 전체에서 같은 용어를 사용한다.
  그래프의 `辺/edge`는 `간선`으로 쓴다. 기하 도형의 변과 구분한다. 방법: 저장본 제목·본문·예제에서 `변`을 검색해 그래프 용례만 확인한다. `불변량` 같은 단어는 바꾸지 않는다.
  `根付き木/rooted tree`는 `루트가 있는 트리`, `非負整数/nonnegative integer`는 `음이 아닌 정수`다. `rooted tree`를 그대로 남기거나 `비음이 아닌 정수`로 쓰지 않는다.
- 분수의 모듈러 값은 정수 나눗셈의 나머지가 아니다. 기댓값은 ‘법 $p$에서의 값’으로
  쓰고, 원문의 $RQ\equiv P\pmod p$ 정의와 유일성 조건을 보존한다.
- 설명은 `합니다`체로 쓰고 요구 동작은 `구하세요` 또는 `출력하세요`로 쓴다. 대화용 말투·접미사(예: `냥`)는 번역 파일에 넣지 않는다.
- 식별자, 문자열, 날짜, 버전, 코드와 실제 예제 데이터는 번역·자동 서식화하지 않는다.
- 불명확한 오타나 원문·예제 충돌은 추측하지 말고 미해결 사항으로 기록한다.
- 일본어 단어 치환으로 번역문을 만들지 않는다.
- 이름 표기는 명시적인 사용자 확정 지시를 먼저 적용한다. glossary에 항목이 없다는 이유만으로 기존 한국어·라틴 표기를 일본어로 되돌리지 않는다. 기존 표기의 근거가 불확실하면 변경하지 말고 문제 번호·현재 표기·원문과 함께 보고한다. 일반적인 재검토·규칙 적용 요청은 이름을 원문으로 복원하는 허가가 아니다.
- 아직 번역하지 않은 인명·팀명·단체명에 사용자 확정 지시와 glossary 대응이 모두 없으면 추정하거나 일부만 음역하지 않고 원문으로 남긴다.
  완료 보고의 확인 요청에 모은다. 일반 용어도 뜻이 불확실하면 사전·공식 자료로 확인한다.
  인명에서 유래한 수학 상수·정리명은 일반 학술 용어다. 표준 한국어 명칭을 확인해 번역하고, 확인되지 않은 항목만 원문으로 남긴다.
- 아직 번역하지 않은 이름과 호칭은 사용자 확정 지시나 glossary의 명시적 대응이 없으면 함께 원문을 유지한다. 이미 확정된 이름·호칭 번역을 되돌리는 규칙이 아니다.
  호칭이 생략되어도 같은 인물인지 문맥으로 확인한다. 예: `物理好き`의 생일 파티를
  ‘물리를 좋아하는 사람들의 생일 파티’로 풀거나, 원문 이름 앞에 뜻풀이를 덧붙이지 않는다.
  예: 아직 미번역인 `eiramくん`에 확정 대응이 없으면 `eiram군`이라는 새 표기를 만들지 않는다. 이미 쓰인 표기를 일본어로 되돌리라는 뜻이 아니다. 일반 음식·아이템명은
  고유명사로 취급해 번역을 생략하지 않는다.
  `格子点大好きbot`은 사용자 확정 표기인 `격자점좋아bot`을 유지한다. 새로 만난 미확정 bot 이름은 뜻이 드러나더라도 임의 번역하지 말고 보고한다. 이름과 그 뒤의 성격·역할 설명을 구분한다.
  `sourceTitle`은 항상 원문을 보존한다. 영어 제목은 `title`도 대소문자·문장부호·난이도 및 버전 표기까지 원문을 유지한다. 예: `Speedrun Query`, `Palindromic Path (Hard)`는 그대로 쓴다. 일본어가 섞인 제목은 일본어 부분만 번역하고 영어 부분은 유지한다. 별도의 명시적 사용자 지시가 있으면 그 지시를 우선한다.
  방법: `이름の問題`는 이름과 `문제`를 따로 분류한다. 제목이라는 이유로 미확정 이름까지 음역하지 않는다.
  본문과 참고 링크에서 명확히 인용한 문제 제목도 같은 기준을 적용하고 URL은 보존한다. 링크 대상과 원문 문맥으로 제목 인용인지 확인하며 일반 용어 설명까지 영어로 바꾸지 않는다. 영어 제목 원문 보존은 본문의 일반 용어에 적용되는 glossary 번역과 구분한다.
  `Writer`처럼 사람의 역할을 나타내는 말은 이름이 아니다. 주변 문장으로 역할인지 확인해 `출제자`로 번역하고, 실제 사용자명만 원문을 유지한다.

## UCPC 참고 근거와 적용 범위

[UCPC 공식 사이트](https://ucpc.me/)와 [공식 GitHub 조직 `ucpcc`](https://github.com/ucpcc)의 [문제 작성·포매팅 지침](https://github.com/ucpcc/problemsetting-guidelines/blob/36cab4ce0df273e5e81e443f00f92ab397f1b007/README.md)을 참고했다. 기준은 2025-08-11 개정, 커밋 `36cab4ce0df273e5e81e443f00f92ab397f1b007`이며 확인일은 2026-10-06이다. 문장 간결성·부연 괄호·정수 범위·TeX 표기 원칙을 이 저장소에 맞게 적용했다. 수식과 목록의 구체적인 작성법은 [문서 구조와 서식](03-structure-and-format.md)을 따른다.

아래는 공식 지침의 조항이 아니라 **기출에서 관찰한 작성 사례와 이 저장소의 적용 판단**이다. 문제 전체의 문체나 서식을 그대로 복제하는 기준이 아니다. 쪽수는 PDF 파일의 페이지 순서다.

| 출처 | 관찰과 적용 |
| --- | --- |
| [2025 본선 D 「Wildcard and Query」, 7쪽](https://static.ucpc.me/archive/ucpc/ucpc-2025/final/problem-ko.pdf#page=7) | 정의에 인접한 예시로 매칭과 유일한 매칭을 구별한다. 정의를 설명하는 본문 예시를 예제 절로 일괄 이동하지 않는다. |
| [2024 본선 F 「4색 정리」, 12쪽](https://static.ucpc.me/archive/ucpc/ucpc-2024/final/problem.pdf#page=12) | 조건 목록 안에 순서 있는 절차를 두고 성립·불성립을 그림으로 설명한다. 목록의 논리 관계와 그림의 설명 위치를 보존한다. |
| [2026 본선 C 「C4ESAR」, 6쪽](https://static.ucpc.me/archive/ucpc/ucpc-2026/final/problem-ko.pdf#page=6) | 허용 연산의 목록과 예제를 실행하는 순서가 구분되어 있다. 조건 나열과 실행 절차를 구별한다. |

UCPC는 출제 지침이고 이 저장소는 번역 지침이므로 다음 차이를 유지한다.

- 입력 절에 범위를 붙이는 방식 대신 **입력 형식과 제한을 분리**한다. 형식으로 명확한 줄 수·공백·변수 설명을 반복하지 않으며, 추가 의미가 필요한 설명만 남긴다.
- 변수 대소문자·인덱스 시작값·EOF 종료·공백 포함 문자열은 원문 사양을 따른다. 출제 단계의 권장을 번역 과정에서 사양을 바꾸는 근거로 삼지 않는다.
- 기존 `합니다`체와 `구하세요`·`출력하세요`, 사용자 확정 이름, 자연스러운 한국어 수량 표현을 유지한다. 짧은 문장·괄호 줄이기 등의 권장을 기존 승인본 수정이나 일괄 치환의 허가로 해석하지 않는다.
